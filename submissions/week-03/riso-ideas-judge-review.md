# 评委视角评审｜Riso 四个候选方案（Monad Builder Camp）

> 评审人：以 Monad Builder Camp 导师/评委视角
> 对象：Riso 提交的四个 Demo 创意
> 日期：2026-07-24
> 背景：团队（Neo/Riso/eleven）已锁定 Week 3 Mini Demo 方向为「自然语言 swap 确认助手」，四个方案为 Riso 个人额外提出的备选灵感。

---

## 一、评审维度说明

| 维度 | 权重 | 说明 |
|------|------|------|
| **Monad-native** | 25% | 是否真正利用 Monad 的高吞吐、低延迟、低成本、并行执行或 EVM 兼容优势，而非只是把以太坊项目搬到 Monad。 |
| **AI × Web3 主题契合** | 20% | 是否与课程/黑客松的 AI × Web3 主题直接相关。 |
| **Moss 原生能力利用** | 15% | 是否能调用 Moss 的 action/simulate/Receipt parser 等能力，复用团队 Week 2 积累。 |
| **技术创新 / 实现深度** | 15% | 合约、前端、链上逻辑是否有足够技术厚度，能在 Demo 中展示代码能力。 |
| **Demo 冲击力 / 叙事** | 15% | 3 分钟 pitch 是否抓人，是否能在 Demo Day 留下记忆点。 |
| **新颖性 / 避免同质化** | 10% | 是否避开常见的 AI-agent/DeFi/预测市场方向，具备少见的概念锐度。 |

> 注：用户价值、商业模式在本次 Tech-track 黑客松中为次要考虑，但不完全忽略。

---

## 二、逐项评审

### 方案 1：全民攻敌 / EVERYONE VS. THE BOSS

| 维度 | 评分（5 分制） | 简评 |
|------|----------------|------|
| Monad-native | ★★★☆☆ | 多人并发攻击 BOSS 确实能体现低延迟，但核心逻辑（Commit-Reveal + 独立伤害槽）在任何 EVM 链都能跑，不非 Monad 不可。 |
| AI × Web3 主题 | ★☆☆☆☆ | 完全没有 AI 元素，与课程主题偏离。 |
| Moss 利用 | ☆☆☆☆☆ | 未使用 Moss。 |
| 技术深度 | ★★★☆☆ | Commit-Reveal、独立记账、状态冲突处理有中等复杂度，但合约体量有限。 |
| Demo 冲击力 | ★★★☆☆ | 社会凝视 + 搭便车有叙事感，适合社会实验，但 Tech Demo 缺少技术爆点。 |
| 新颖性 | ★★★☆☆ | 公共品博弈游戏在链上并不少见（如 Gitcoin、各种 coordination games），包装口号不错，但概念并非罕见。 |

**评委一句话**：一个合格的游戏化社会实验，更适合 Research/Ops 叙事，对 Tech track 和 AI × Web3 主题帮助不大。

---

### 方案 2：BOSS IS LEARNING

| 维度 | 评分（5 分制） | 简评 |
|------|----------------|------|
| Monad-native | ★★★☆☆ | 每轮多人并发提交、链上更新 BOSS 抗性需要吞吐，但频率未必高到必须 Monad。 |
| AI × Web3 主题 | ★☆☆☆☆ | BOSS "学习" 只是规则更新，没有真正的 AI Agent 参与。 |
| Moss 利用 | ☆☆☆☆☆ | 未使用 Moss。 |
| 技术深度 | ★★★☆☆ | 信息熵/在线学习算法上链有亮点，但演示时观众未必感知到技术难度。 |
| Demo 冲击力 | ★★★☆☆ | "最优解反而害死所有人" 有传播点，但视觉表现容易变成普通策略游戏。 |
| 新颖性 | ★★★☆☆ | 动态难度 + 群体多样性议题有新意，但游戏形态仍属常见链游框架。 |

**评委一句话**：比方案 1 更有概念锐度，但更像一个链游 + 社会观察，缺少 Monad 不可替代性和 AI 元素。

---

### 方案 3：忒修斯之船：最后的 BOSS

| 维度 | 评分（5 分制） | 简评 |
|------|----------------|------|
| Monad-native | ★★★☆☆ | 并发修改不同组件可以提并行执行，但游戏本身对吞吐要求不高。 |
| AI × Web3 主题 | ★☆☆☆☆ | 无 AI 元素。 |
| Moss 利用 | ☆☆☆☆☆ | 未使用 Moss。 |
| 技术深度 | ★★☆☆☆ | BossRegistry + 组件替换 + 投票，合约逻辑简单，主要是叙事驱动。 |
| Demo 冲击力 | ★★★★☆ | 哲学命题（身份来自编号、内容还是历史）容易在 pitch 中制造记忆点。 |
| 新颖性 | ★★★★☆ | 把忒修斯之船做成可交互链上实验，概念少见，艺术感强。 |

**评委一句话**：最有叙事和美学潜力，但技术实现偏轻，更像艺术/哲学 Demo，不太符合 Tech track 对工程深度的期待。

---

### 方案 4：不是我干的 / NOT MY FAULT

| 维度 | 评分（5 分制） | 简评 |
|------|----------------|------|
| Monad-native | ★★★★☆ | 多审批房间、快速确认、低成本交易、链上责任时间线，都直接对应 Monad 优势；未签名交易模拟也是 Monad/Moss 原生能力。 |
| AI × Web3 主题 | ★★★★★ | 直接讨论 AI Agent 提议交易 + 人类层层批准的代理问题，是课程核心议题。 |
| Moss 利用 | ★★★★★ | 明确使用 Moss 构造和模拟未签名交易，与团队 Week 2 积累完全契合。 |
| 技术深度 | ★★★★☆ | DecisionLedger 合约、四角色审批链、风险警告记录、责任时间线，有完整链上/链下闭环。 |
| Demo 冲击力 | ★★★★★ | "AI 提议，人类背锅" 是当下最热也最有争议的话题，3 分钟 Demo 能做出强烈张力。 |
| 新颖性 | ★★★★★ | 不是又一个 AI 交易机器人或 DeFi 聚合器，而是把 AI Agent 的"责任黑洞"问题搬到链上审计，非常少见。 |

**评委一句话**：四个方案中唯一同时满足 Monad-native、AI × Web3、Moss 原生、技术深度和 Demo 冲击力五个条件的方案。

## 四、与团队当前 Mini Demo 方向的对比

团队当前锁定方向：**自然语言 swap 确认助手**

| 对比项 | 当前方向 | Riso 方案 4（不是我干的） |
|--------|----------|---------------------------|
| 用户问题 | 链上新手看不懂 Agent 返回的交易 | AI Agent 时代责任分散、Human in the Loop 失效 |
| Monad 价值 | 低延迟让 simulate → 确认页体验流畅 | 低成本 + 快速确认让多角色审批房间可运行 |
| Moss 使用 | 核心：action/simulate/Receipt 解析 | 核心：构造和模拟未签名交易 |
| AI 叙事 | AI 帮用户表达意图 | AI 与人类之间的责任边界 |
| 新颖性 | 中等（交易解释层已有类似产品） | 高（责任审计是很少被链上化的方向） |
| Week 3 可行性 | 高（已跑通 Kuru swap） | 中（需要额外设计 DecisionLedger 合约和四角色流程） |

**评委判断**：
- 如果目标是 **Week 3 稳定交付并留下 Demo Evidence**，当前方向更稳妥。
- 如果目标是 **Week 4 Hackathon 做出差异化、高冲击力作品**，方案 4 更值得升级。

## 五、评委建议

### 给 Riso

1. **方案 4 不要丢**：这是四个灵感中唯一能把「AI Agent + Moss + Monad + 链上责任审计」串成闭环的创意。建议把它作为 Week 4 Hackathon 的首位备选方向。
2. **弱化游戏化方案**：方案 1/2/3 虽然叙事有趣，但偏离 AI × Web3 主题，且与团队已有的 Moss 能力无关，在 Tech track 中竞争力不足。
3. **强化"责任时间线"的可视化**：如果未来做方案 4，Demo 的核心不是审批通过与否，而是「事后还原：谁看见警告、谁仍然批准」这一条不可篡改的链上证据链，这是最有传播力的画面。

### 给团队

1. **Week 3 继续走当前 Mini Demo**：自然语言 swap 确认助手已验证技术可行，能在本周留下 Evidence，优先完成。
2. **Week 4 把方案 4 作为正式备选**：Mini Demo 结束后，团队可以讨论是否把「不是我干的」作为黑客松主方向，或把当前 swap 助手的"确认页解释能力"嫁接到方案 4 的"审批前风险提示"中。
3. **避免在四个游戏方案中消耗太多资源**：它们更适合作为个人创意卡片存档，而不是团队主战场。

---

## 六、关键结论

> **从 Monad 评委视角看，Riso 的四个方案中，只有「不是我干的」具备在 Tech track Hackathon 中冲击高分的潜力。**
>
> 它同时满足：
> - 真实的 AI × Web3 命题（Agent 责任边界）
> - 原生使用 Moss（未签名交易模拟）
> - Monad 性能价值（多审批房间低成本快速确认）
> - 少见且不同质化的概念（链上责任审计）
> - 强烈的 Demo 叙事张力（Human in the Loop 是橡皮图章吗？）
>
> 其他三个方案更像链游/社会实验，可以作为创意储备，但不建议作为 Tech track 主方向。
