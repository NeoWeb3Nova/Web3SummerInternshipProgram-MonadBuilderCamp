## Co-Learning｜Team Matching 话术

### Idea Holder｜60 秒（Neo / 团队代表）

我们想做 **Agent 钱包交易黑匣子**。

用户让 AI Agent 帮自己做一笔 Swap 时，签名前往往看不懂 Agent 到底要授权什么；一旦结果异常，又只能在聊天记录、钱包弹窗和区块浏览器之间手工拼接事实。

我们第一版只做一笔 Swap：Moss 构造并模拟交易 → 页面解释资产变化与风险 → 用户确认 → 生成可验证的决策收据（可选把哈希锚定到 Monad）。它不替任何人判责，只保证事后能核验当时发生了什么。

**已有角色：** Dev（我）、Product/Research（Riso）、UI（eleven）。  
**可选招募：** 熟悉钱包安全 / 链上审计的开发者。  
**本周先做：** 3 人真实访谈 + 技术边界验证，不急着堆功能。

### Builder｜30 秒（Neo 个人）

我是 **Neo**，Dev / Tech Lead。  
**可贡献：** Moss Kuru `action → simulate` 链路复用、决策收据数据结构、真实 vs Mock 边界、端到端技术 Demo。  
**本周交付：** 一笔 Swap 能否稳定产出结构化证据的验证记录。  
**投入：** 约 6 小时/周。  
**不单独扛：** 用户访谈组织与 UI 可读性——分别由 Riso 与 eleven 负责。

### 落单同学可回应的钩子（若有人想加入）

|----------------|------------|

## 下一步（Day 4 入口，不是立刻堆功能）

团队下一步是完成一次 **3-Person Reality Check**：

1. **Riso** 访谈 3 位使用过 AI Agent、钱包或 DeFi 的个人用户，重点问：最近一次盲签 / 误解交易 / 事后核对经历。
2. **eleven** 用一张低保真流程图，测用户能否看懂「Agent 提议了什么 → 模拟发现了什么 → 用户确认了什么 → 最终执行了什么」。
3. **Neo** 验证一笔 Moss Swap 能否稳定产出决策收据所需证据，并列出必须真实运行 vs 可 Mock 的边界。
4. 三人根据证据选择：**继续 / 缩小 / 调整 / 合并 / 暂停**；只有需求与技术风险基本成立，才在 Day 5 写 Start Card 进入 Build Sprint。

| 触发条件 | 调整动作 |
|----------|----------|
| 用户只关心签前解释，不需要事后证据 | 缩小为「Agent 交易知情确认」，复用 Week 3 确认页能力 |
| 个人用户痛感弱，DAO/金库更痛 | 调整目标用户，或与责任审计类 Idea 合并 |
| 技术上难以稳定产出证据 | 扩大 Mock 边界，先验证 UI 与需求，技术债写进 Start Card |
| 投入或目标不再匹配 | 成员可重新匹配；优先保证 Demo 仍可由剩余角色展示最小闭环 |

说明：拆队不是首选，但目标或时间不再匹配时允许重新组队。组队**不等于**一次决定后永远不能改。
