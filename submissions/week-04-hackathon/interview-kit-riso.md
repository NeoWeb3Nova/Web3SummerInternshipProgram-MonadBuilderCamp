## 0. 今天要验证什么（一句话）

使用 AI Agent / 钱包做 Swap 的个人用户，是否会在**签名前看不懂**、**事后拼不齐事实**，并且是否愿意看/保存一份「决策收据」。

**Persona 预演已提示：** 更可能先验证「签前解释 + 交易版本绑定」，完整责任时间线待真人确认。不要把预演当证据。

## 1. 找谁谈（3 人差异化）

尽量覆盖不同层级，避免 3 个同质群友：

| 优先级 | 画像 | 为什么相关 | 去哪找 |
|--------|------|------------|--------|
| 必有 | 用过 AI 帮写交易 / Agent 钱包 / 聊天式 DApp 的人 | 最贴近目标用户 | 营内、Agent 钱包群、用过相关产品的同学 |
| 必有 | 做过 DeFi Swap，但看不懂授权/calldata 的个人用户 | 签前盲点最强 | Web3 新手群、Week 1–2 同学 |
| 建议 | 有过「结果和预期不符再对账」经历的人（不一定用 Agent） | 验证事后还原是否真痛 | 做过亏 gas / 滑点 / 错误 approve 的人 |
| 可选加分 | 钱包安全 / 合约开发者 | 边界与证据格式 | 技术同学（当压力测试，不当唯一用户） |

**合格门槛：** 3 人中至少 2 人最近 3 个月有过钱包确认 / Swap / 授权相关经历。  
若 3 人都没经历过 → 任务仍算完成，结论可能是 **暂停 / 调整**，不是失败。

**时间：** 每人 **12–15 分钟**（文字语音均可）。

## 2. 邀请话术

### 2.1 群内 / 私聊（中文 · 推荐）

```text
嗨！我们在做 Monad Playground 的一个小调研（约 12–15 分钟），
不是推销产品，也没有正确/错误答案。

想了解：你用钱包或 AI 帮忙做链上操作（比如 Swap）时，
签名前有没有「其实看不太懂但还是点了确认」的经历；
如果结果和预期不一样，你事后是怎么核对的。

形式：微信语音/文字都行。可以匿名，我们只记摘要用于作业。
方便的话今天/明天哪个时段可以聊几句？谢谢！
```

### 2.2 更短版（评论区 / 群公告）

```text
【12 分钟用户访谈 · 不推销】
做过钱包 Swap / 授权 / 用过 AI 帮交易的朋友，想请教一次真实经历：
签名前最担心什么？结果不对时怎么对账？
私聊我约个空档，可匿名。谢啦！
```

### 2.3 English（若跨时区 / 英文营友）

```text
Hi! Quick 12–15 min research chat for a Monad hackathon (not a pitch).

Curious about a real experience: last time you signed a wallet tx
(or used an AI agent for a swap) — what was confusing before signing,
and how did you reconcile if the result looked wrong?

Anonymous notes only. Free for a voice note or text today/tomorrow?
```

### 2.4 开场 30 秒（接通后）

```text
谢谢你抽时间。我们想做「Agent 帮你准备 Swap 时，人能不能知情确认、
事后能不能还原当时发生了什么」。

我不会推销功能，主要听你的真实经历。
你可以说「没遇到过」——这对我们也很有价值。
可以匿名，记录只用于课程作业。准备好的话我们开始？
```

### 2.5 结束与是否愿意试用

```text
超级有帮助。最后两个小问题：
1）如果只能改进一件事，你最希望是什么？
2）如果有一个「签名前用一句话说清付出/收到/风险，并本地保存一份可核对摘要」的第一版，你愿意试一下吗？为什么？

感谢！如果后续有 5 分钟 Demo，我可以再找你看一眼——不勉强。
```

## 3. 正式访谈问题（按顺序）

> 核心 6 问来自课程；下面是追问与记录提示。  
> **禁止主问题：**「你觉得我们这个 Idea 好不好？」

| # | 主问题 | 追问（选 1–2 个） | 你要记下什么 |
|---|--------|-------------------|--------------|
| 0 | 你最近一次用钱包 / Agent / DeFi 大概是什么场景？ | 频率？主要用什么产品？ | 是否目标用户 |
| 1 | 你最近一次遇到「签名前看不太懂」或「事后对不上账」是什么时候？ | 大概多久以前？金额大吗？ | 是否真实发生过 |
| 2 | 当时你是怎么解决的？ | 截图？问人？取消？小金额试？浏览器？ | 现有替代方式 |
| 3 | 哪一步最麻烦、最担心或最浪费时间？ | 授权？滑点？地址？结果不符？ | 最痛一步 |
| 4 | 现有办法为什么不够好？ | 缺什么信息？信不过谁？ | 替代方案缺口 |
| 5 | 如果只能改进一件事，你最希望是什么？ | 签前一句话？绑定同一笔 tx？本地收据？ | 优先级信号 |
| 6 | 你是否愿意体验我们的第一版？ | 什么条件下愿意/不愿意？ | 试用意愿 |

### 可选探针（时间够再问）

- 你有没有保存过 Agent 聊天记录 + 钱包记录去对账？
- 「模拟结果」和「最终成交」不一致时，你怎么判断是谁的问题？
- 若收据要上链，你接受「只上哈希、详情本地」吗？还是完全不要链上？
- 你更需要：**签前看懂**，还是 **事后还原**，还是两者都要？

### 红旗（听到要记，可能改范围）

| 信号 | 可能含义 |
|------|----------|
| 「我从来不用 Agent，自己操作也还行」 | 目标用户过窄 |
| 「我只在乎价格，不在乎解释」 | 签前解释价值弱 |
| 「事后我从不回看」 | 黑匣子/收据需求弱 → 缩小到签前 |
| 「我要的是自动执行、少确认」 | 与安全边界冲突，非目标用户 |
| 「必须能证明法律责任」 | 产品边界：只记事实，不判责 |

## 8. 隐私与安全

- 不记录助记词、私钥、完整地址（可用 `0xabc…123`）。
- 不外传队外原话截图（除非对方同意）。
- 金额可写「小额 / 三位数 USDC」量级，不必精确到分。
