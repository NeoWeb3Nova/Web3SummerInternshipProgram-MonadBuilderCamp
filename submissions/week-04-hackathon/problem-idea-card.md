## 问题句

> 当使用 Agent 钱包的个人用户准备执行一笔链上交易时，想确认 Agent 是否忠实执行了自己的意图，却因为看不懂交易提案和模拟结果，也无法在出错后还原「Agent 提议—风险提示—用户确认—实际执行」的完整过程而遇到困难，目前只能依赖钱包确认弹窗、聊天记录和区块浏览器手工拼接事实。

## Idea 卡片

| 字段 | 内容 |
|------|------|
| **Idea 暂定名** | **Agent Wallet Flight Recorder｜Agent 钱包黑匣子** |
| **目标用户** | 使用 AI Agent 准备或执行链上操作、但无法独立阅读 calldata、Capability 树和事件日志的个人钱包用户。 |
| **场景** | 用户让 Agent 执行一次 Swap。签名前，他需要知道 Agent 准备做什么、资产会怎样变化、有哪些风险；如果结果与预期不符，他还需要还原当时看到了什么、确认了什么，以及链上最终执行了什么。 |
| **障碍** | 钱包弹窗只展示地址、金额和 Gas；Agent 对话、模拟结果、用户确认与最终交易分散在不同系统中。用户既难以做出知情确认，也缺少一条可验证的事后证据链。 |
| **现有替代方式** | 截图或保存 Agent 聊天记录，再结合钱包记录和区块浏览器逐项核对；这些信息缺少统一结构，也难以证明记录是否被修改。 |
| **为什么值得验证** | Week 3 构建自然语言 Swap 确认助手时，我们已经遇到同一问题：Moss 可以生成并模拟未签名交易，但普通用户仍需理解 Capability、Receipt 和 Warning 后才能决定是否签名。团队因此明确保留用户确认、不让 Agent 自动签名，并把「付出 / 收到 / 风险」作为确认页核心。值得进一步验证的是：用户是否不仅需要签名前解释，也愿意保存一份可验证的“决策收据”，用于交易异常后的事实还原。 |
| **我能提供的切入** | **开发 / 产品**：复用已经跑通的 Moss Kuru `action → simulate` 链路，设计决策收据的数据结构，并实现一条 Swap 的端到端 Demo；同时负责划清“记录事实、不替法律判责”的产品边界。 |
| **技术概念 vs 用户问题** | **是**。核心不是“把日志上链”，而是解决个人用户无法知情确认、无法在交易异常后还原事实的问题。 |
| **Moss 关联（可选）** | Moss 负责构造未签名 Capability、模拟交易并输出有序 Receipt / Warning。Demo 将用户意图、Agent 提案、模拟结果、风险提示、用户确认和最终交易组织成一份可核验的决策收据。 |
| **Monad 关联（可选）** | Monad 的低延迟适合把模拟与解释放进签名前实时流程；低成本适合为每份决策收据锚定哈希。敏感详情保存在本地，链上只保存承诺哈希和必要时间线。 |

## 我想做什么？

> 我想做一个 **Agent 钱包交易黑匣子**，帮助 **使用 AI Agent 操作链上资产的个人用户**解决 **签名前看不懂自己将授权什么、交易出错后又无法还原 Agent 提议与实际执行过程**的问题。

首版只演示一条完整链路：

> 用户要求 Agent 执行一次 Swap → Moss 构造并模拟交易 → 页面解释资产变化和风险 → 用户确认 → 生成可验证的决策收据，并将收据哈希锚定到 Monad。

它提供的是一条可验证的事实证据链，不替用户、Agent 开发者或法律系统判定责任。

---

## 为什么想做这个？

Week 3 做自然语言 Swap 确认助手时，我发现真正困难的并不是让 Agent 生成一笔交易，而是让用户判断：

- Agent 生成的交易是否忠实对应了我的原始意图？
- 模拟暴露了哪些资产变化与风险？
- 我确认的是不是后来真正广播的那笔交易？
- 如果结果异常，聊天记录、钱包弹窗与链上交易能否组成可信的事实链？

目前用户只能在 Agent 对话、钱包确认页和区块浏览器之间手工核对。随着 Agent 钱包开始处理更多真实资产，这种信息断裂会让“Human in the Loop”退化成盲点确认。因此，我想验证用户是否需要一份由结构化证据支持、内容可核验但敏感信息不必全部公开的决策收据。

## 1 分钟 Idea Market 分享稿

我想做一个 **Agent 钱包交易黑匣子**，帮助使用 AI Agent 操作链上资产的个人用户，在签名前看懂自己将授权什么，并在交易出错后还原 Agent 提议、风险提示、用户确认与实际执行之间发生了什么。

这个想法来自我们 Week 3 的真实开发过程。我们已经能用 Moss 构造和模拟一笔 Swap，但发现用户面对 Capability、Receipt 和钱包弹窗时，仍然很容易变成盲点确认；一旦结果异常，Agent 对话、模拟结果和链上交易又是割裂的。

第一版只演示一笔 Swap：Moss 生成并模拟交易，用户看懂资产变化与风险后确认，系统生成一份决策收据，并把收据哈希锚定到 Monad。它不替任何人判责，只保证事后能核验当时究竟发生了什么。

我负责 Moss 集成和技术实现，现在希望找到设计、用户研究或产品伙伴，一起验证用户是否真的需要这样的 Agent 交易证据链。
